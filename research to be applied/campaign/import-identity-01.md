# IMPORT-IDENTITY-01 — imported attempts, personal bests, and teaching references

## Scope

Read-only trace of the recording importer, storage index, personal-best selector, ghost playback, reference eligibility, UI labels, and existing tests in `work/reviewed-training`. No private player data, code changes, game session, or tests were used.

## Direct answer

**Yes.** A structurally valid imported JSON can be selected by the automatic `personal_best` route as “Your Best Attempt” if it claims `metadata.source.kind == "local_player"`, has `outcome == "success"`, is not truncated, and passes the selector's speed checks. `import_recording()` preserves the imported `metadata.source` and does not require permission for a personal import. Missing `game_speed` fields pass validation and are treated as `1.0` by `personal_best()`. The selector ignores `import_status` and does not compare game version, hitbox, map, mutators, or starting state because its production caller supplies no compatibility candidate.

The later ghost load has a stricter live-setup compatibility check. It may reject a selected recording whose declared setup differs from the current lesson, but that check occurs after `personal_best()` has selected and labelled one item; this bridge path does not fall through to the next compatible recording. A matching imported claim can proceed as personal playback. Neither path independently proves who captured the file.

## Teaching-reference selection is separate and currently absent

The lesson catalog has `reference_recordings: []` and says “Real successful demonstration required; none bundled” (`training/catalog.py:73-74`). The app's QML displays `reference_status` but has no reference picker (`Main.qml:464-465`). `reference_availability()` can inspect candidates, but repository search found no production call site; it is used in tests. The bridge rejects `play_recording` `kind` values other than `personal_best`, and the explicit/automatic worker loads call `GhostPlayback.load(..., kind="personal")` (`bridge.py:1513-1555`; `game_worker.py:1057-1063`). Thus the code has reference-validation helpers, but no current UI flow selects and plays a teaching reference.

With `require_reference=True`, validation demands `source.kind == actual_execution`, a nonempty origin, `permission.distribute is True` plus a nonempty permission basis, nonempty success evidence, successful outcome, complete (not truncated) recording, and known game/framework/hitbox/map fields (`recordings.py:99-120`). These are **metadata claims**, not independent proof or verified license status: `recording_provenance()` always sets `independently_validated: false` and warns that source metadata is not validation (`training/coach.py:77-106`). Even the helper's `reference_eligible` label means only that structural claims passed. `reference_availability()` sets `validated_demo_available: false` and describes supplied success/permission as unverified (`coach.py:110-136`).

## Honest labels and smallest contract change to consider

- Keep imported playback available as **Imported attempt** with its source claim visibly marked unverified. A JSON `source.kind` or user-entered label must not make it appear app-captured.
- Reserve **Your Best Attempt** for recordings whose ingestion as an MCT-observed local attempt is stored outside the imported JSON claim. The current index does not record that ingestion origin. Store an app-authored `capture_origin` in the application-owned index, set by the separate capture/import routes; never accept that field from an imported file. The automatic personal-best selector should require the app-owned capture origin and exclude imports unless the product intentionally supports “best imported attempt.”
- Pass the current `practice_context` into personal-best selection so incompatible metadata is filtered before duration comparison. If no compatible candidate remains, report that setup mismatch directly; do not select an incompatible shorter recording and fail only during load.
- Keep **Teaching reference** unavailable until an actual execution and distribution permission have been independently reviewed. Until then, use **Reference candidate — claims unverified** for a structurally eligible import, never “verified demonstration.” In the pause page, replace “validated trace” with **loaded recording** or **format-checked recording**. Importing a private personal recording and authorizing redistribution are separate decisions.
- Change “Import permitted recording” to language such as **Import a recording you have permission to use** if permission remains the user's responsibility; explain that the app does not verify source or license. The UI already distinguishes the teaching-reference status, but it must not imply that import itself certifies anything.
