# DOWNLOAD-01 — Community plugin discovery and download audit

**Scope:** Read-only source and public-site research. No package was installed, extracted to a game folder, enabled, or tested in Rocket League. Source/test coverage is not a runtime-compatibility claim.

## Confirmed flow

1. **Discover:** `community_discovery.fetch_catalog` reads one fixed-host HTTPS HTML page at a time. BakkesPlugins rows are link-only metadata with canonical numeric `source_id`, title/creator, details URL, `catalog_only`, `can_activate: false`, and `installed_state: unknown`. Query is local to the already-fetched page; remote search is not used. Page body is capped at 2 MiB, 60 rows, 50 pages, with bounded text/IDs and redirect/TLS validation. Thumbnails are metadata only; no network request fetches them (`src/my_career_training/community_discovery.py:1-32,47-87,138-231,391-432,755-778`).
2. **Select/check release:** The bridge accepts a plugin selection only when its source and ID match a row from the current catalog page, then sends its numeric ID to `community_plugins.lookup_plugin`. The alternate Mods panel accepts a numeric ID or exact canonical HTTPS `bakkesplugins.com/plugin/<id>` page URL. It does not fetch arbitrary caller URLs. The adapter calls the fixed short-metadata endpoint and requires an exact one-plugin response key, an integer `version` in range, a URL, and a boolean `verified` (`src/my_career_training/bridge.py:626-633,1152-1179`, `src/my_career_training/community_plugins.py:135-150,258-339`).
3. **Download:** The checked record is revalidated against fresh metadata immediately before fetching. If the API version or download URL changed since lookup, it refuses the stale record and the player must check the release again. The archive URL must be HTTPS on `cdn.bakkesplugins.com/uploads/<filename>.zip`; each redirect is checked, TLS certificate and hostname checks are required, and only `application/zip` or the observed `application/x-zip-compressed` alias is accepted. Metadata/archive limits are 64 KiB/8 MiB; timeouts are 20/60 seconds; reads are in 64 KiB chunks with a 3-redirect limit (`src/my_career_training/community_plugins.py:70-89,153-205,342-361,372-452,491-537`).
4. **Inspect/cache:** The ZIP is never extracted. Inspection caps it at 64 entries, 32 MiB expanded total, 16 MiB per file and 50:1 compression; it rejects encrypted/link/special files, unsafe or duplicate case-insensitive names, unsupported compression and CRC/size mismatches. The receipt contains the archive SHA-256, release metadata and a bounded member listing. A content-addressed `objects/<sha256>/archive.zip` plus receipt is written via staging and atomic renames. Later library checks re-read the archive without following links, re-hash it and re-inspect the ZIP. Cache status is explicitly `downloaded_not_enabled`, `can_activate: false` (`src/my_career_training/community_plugins.py:540-617,712-783,814-939`).
5. **Cancel/retry:** Plugin operations run on one daemon worker; a shared busy flag prevents another plugin request until the terminal result is polled. Cancel sets an event; archive streaming, inspection and staging check it. Cancellation before the final publish removes staging and reports cancelled. A cancel racing with the atomic publish is intentionally reported as success so a committed archive is not hidden. A download failure clears busy and leaves the selected release available to retry; if the release changed, re-check is required. Lookup itself has no cancellation callback, and a download must also complete its initial fresh metadata lookup before observing cancellation (`src/my_career_training/bridge.py:293-383,794-798,2148-2153,2271-2280`, `src/my_career_training/community_plugins.py:135-150,153-205,515-537,841-893`).
6. **Display:** Desktop and native UI expose check, download, cache-check and cancel controls. While busy, the UI shows a text status and Cancel. The download module has an optional byte-progress callback, but the bridge does not pass one and neither UI displays bytes or percent. Completion says “Downloaded. Not enabled”; the library row displays the plugin ID and not-enabled state, while the native selected-item detail also shows the site’s verified flag (`src/my_career_training/ui/Main.qml:516-545`, `plugin/src/CareerUI.cpp:450-474`, `src/my_career_training/community_plugins.py:153-160,515-537`, `src/my_career_training/bridge.py:303-383`).

## Published listing, release, license and compatibility boundaries

- The official [BakkesPlugins browse page](https://bakkesplugins.com/plugins) lists public entries; an inspected [plugin page](https://bakkesplugins.com/plugin/223) shows the creator, page version/date, description, and a source-code link. The site’s [submission guidance](https://bakkesplugins.com/wiki/bakkesmod-sdk/useful-info/submitting-to-bakkesplugins) says a submission supplies a source ZIP and semantic version and describes an automated build and moderator review before approval. This is evidence about that platform’s listing/review process, not proof that a release works with the user’s installed game/BakkesMod build.
- The project adapter’s API `version` is an integer. Its saved observation for the example page records API version 21 while the page labels the release 1.16.1. The adapter does not carry the page’s semver separately into the live selected/downloaded record; avoid displaying the integer as a semantic plugin version unless the site’s field meaning is confirmed. The short API response does not provide title or creator: only a curated snapshot has those fields, and other numeric IDs fall back to “Community plugin <id>” / “See creator page” (`src/my_career_training/community_plugins.py:8-27,97-127,240-250,287-294,312-339`).
- The adapter labels the site’s `verified` boolean as a platform review state, not a signature or artifact attestation. The SHA-256 is computed after download and then detects cache corruption; no published digest/signature is checked. The ZIP member listing does not inspect code behavior, DLL ABI, dependencies, supported game build or online safety.
- Neither the API/receipt schema nor the inspected page exposes a normalized license field. A source link or public download is not a license check. The project’s `docs/BUILD_SPEC.md:148-152` calls for creator/source/license/compatibility notes, and its `docs/TRAINING_WORKSHOP_DIRECTION.md:183-195` says listing is not certification and activation requires a compatible verified integration. Keep license unknown until the original terms are checked; keep runtime compatibility unavailable until a separate exact-build integration test passes.
- The current project status reports a successful official archive download and cache validation for its separate pinned controller-overlay feature, plus in-game discovery selecting a listed plugin and finding its current release. General community-plugin activation remains unavailable; these facts do not establish generic plugin installation/loading compatibility (`docs/PROJECT_STATUS.md:24-33,65-75`, `docs/TRAINING_WORKSHOP_IMPLEMENTATION.md:52-77,127-137`).

## Concrete gaps and bounded failure behavior

- **No byte progress is presented.** The download function can report `(received,total)`, but no bridge callback/state field or QML/ImGui progress control wires it through.
- **Metadata lookup is not promptly cancellable.** Cancel is cooperative only after an API lookup returns; a direct release check or the fresh pre-download lookup can remain busy until the 20-second request timeout. Archive cancel is checked between reads, so a blocked read can also wait for its network timeout.
- **Cache is per-artifact bounded, not aggregate-bounded.** Each archive and ZIP is size-limited, but the `objects` cache has no total-size/count cap or eviction path. Each new release has a new content hash. No general downloaded-plugin delete action was found. Stale `.staging-*` folders are cleaned on the next publish; a canceled/failed publish normally cleans its staging folder.
- **Disk errors are caught and surfaced as a storage error, and atomic-write temporaries/staging are cleaned in ordinary exceptions.** Existing tests exercise cancellation during staging, but no focused test injects write/fsync/rename/space failures and verifies the visible retry route.
- **Selection metadata is lossy for non-curated plugins.** The catalog row has title/creator, but selecting it routes only the ID to the release lookup; the short API lacks those fields, so the detail panel can revert to generic fallback. The downloaded row UI shows only ID/status even though the local receipt has the integer API version and SHA.
- **Close signals cancellation without joining the daemon worker.** The worker only owns the private plugin cache, not the game or save. A shutdown during a blocked request has no guaranteed final UI acknowledgement; interrupted staging is ignored by cache listing and is cleaned on a later publish.
- **Cache listing is integrity/offline checking, not update checking.** It does not contact BakkesPlugins, so an intact cached archive can be an older published release; the separate “Check release” action is what gets current metadata.

## Six-part player action contract

1. **Preconditions:** A current BakkesPlugins row or valid numeric ID/page link; no plugin request already busy; a private writable cache. Show source, creator, available page release, site verification meaning, and unknown license/runtime compatibility before download.
2. **Input:** Select a current catalog row or enter the official ID/page URL; choose **Check current release**, then **Download to library**. Allow **Cancel** while a request is active.
3. **Visible/state outcome:** Show the selected published release and whether the site marks it verified; during transfer show bytes/percent and Cancel; on success show exact item/release, digest/cache status and “Downloaded, not enabled.” Never present the site marker as runtime compatibility.
4. **Persist:** Keep the original bounded ZIP and receipt in the app-private content-addressed cache; no extraction or game/BakkesMod writes occur in this function. Cache identity is the archive digest, not just the plugin ID.
5. **Failure/recovery:** Invalid IDs/URLs fail before network access. Network, changed-release, malformed ZIP and disk failures leave the game untouched and produce a retryable error. Pre-commit Cancel leaves no visible package; post-commit Cancel keeps and reports the committed package. Cache corruption is omitted with a clear re-download option; stale staging is cleaned safely.
6. **Acceptance proof:** On the exact candidate, browse/select a real public plugin, verify current page/API metadata, download and independently re-hash the receipt, check progress and cancel/retry at metadata, body and staging phases, force network and disk failures, re-open the cache after restart, and confirm no generic install/load/activation command or game/BakkesMod file change occurred.
