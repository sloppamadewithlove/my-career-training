## Row identity and input route

`TrainingModeRow` is a DataAPI view over table `TrainingMode`, indexed by `RowIndex`. Its fields include integer `Status`, `bOwned`, `bFavorited`, `bOutOfDate`, `Code`, `MapName`, name/creator fields, type/difficulty, round count, and shots completed (`TrainingModeRow.as:7–130`). Native calls use the row index; the selected wrapper exposes no stable GUID or key matching across reorder. A code is available as a field, but no source here proves uniqueness or that the list uses it for selection.

`TrainingModeBrowser` is a thin bridge to `UIShellHooks.SHELL_CallUnrealFunction` on native `GFxData_TrainingModeBrowser_TA.TrainingModeBrowser`. Its wrappers include History, local files, code search, reset, sync operations, and create (`TrainingModeBrowser.as:25–113`). `TrainingBrowserListView` consumes rows from the native `TrainingMode` table rather than filtering them itself. These calls establish the UI-to-native dispatch surface only.

The detail panel creates a state-dependent action list, shows button labels and non-PC glyph markup, and processes the matching navigation code on key-up; panel buttons are not focusable, so controller navigation is mapped directly to actions (`TrainingSequenceDetailsPanel.as:209–233,240–278`). Mouse clicks still reach the panel's `ButtonEvent.CLICK` handler (`:240–248,280–294`). `ModalScrollingList` sets 4-pixel vertical padding, 28-pixel spacing, a default `ModalListItemRendererMovie`, and `BasicScrollBar` (`ModalScrollingList.as:7–39`). `TrainingBrowserListView` overrides that renderer name to `TrainingSequenceListItemMovie` in its constructor (`TrainingBrowserListView.as:28–34`); the row-renderer class was subsequently exported and traced in [pack row composition](native-pack-row-01.md). Its same-movie `ScrollingList` base accepts Up/Down on KEY_DOWN/KEY_HOLD, jumps by the visible renderer count for Page Up/Down, and handles Home/End (`ScrollingList.as:224–325`). The selected item is scrolled into view and scroll position is clamped to the valid window (`:100–129,194–222`). On data refresh, old scroll/selected indexes are clamped by numeric bounds (`:537–544`). Selection therefore follows an index when it remains valid, not a stable pack identity. `CoreList` dispatches `INDEX_CHANGE` when selected index changes and converts renderer click/rollover into index selection (`CoreList.as:187–196,659–678`). The browser consumes `ITEM_CLICK`; in BOUND interaction mode its menu handler also starts `Play(MapName,true)`, while an unhandled row click in the non-BOUND mode only selects the row and updates details (`TrainingBrowserMenu.as:276–278,529–540`).

## Relation to My Career Training

The current app's pack catalog is a fixed six-row metadata excerpt with `lesson:pack:<id>` identity. The browser keeps pack rows visible but marks play unavailable offline; the catalog has no imported pack bytes or native favorite/history bridge. (PACK-01: `src/my_career_training/training/packs.py:1–26,105–132`; `plugin/include/NativeCareerLayout.h:655–670,1552–1632`.) App favorites are separate snapshots keyed by type and ID (`bridge.py:668–731`; `storage.py:24–61`). Thus stock browser behavior can guide category and code-search concepts, but its APIs and installed content state do not imply current MCT pack download/play support.
