# BALL-VISIBILITY-01 — Power Shots timeout ball disappearance

## Scope and finding

Read-only comparison of the BakkesMod SDK headers consumed by the frozen MCT build, its Soccar adapter, RLBot's pinned desired-state fields, and the pinned public default-plugin sources. The MCT CMake file pins BakkesModSDK archive commit `479e8f571cf554b25f4eeb64d611dec4133edcaf` with SHA-256 `e4072d2884a432bedfd7a7e8474000137b1649deeea3346de4f1b2a0cb9dd866` (`work/reviewed-training/plugin/CMakeLists.txt:26–29`). This identifies the declaration source consumed by CMake; it does not establish an installed runtime DLL match.

**Best candidate:** on an explicitly reported Power Shots `timeout`, use the ball-scoped `BallWrapper::FadeOutBall()` and pair it with `FadeInBall()` when the next attempt is reset or the owned session is leaving. Its ball-specific API and named inverse make it a focused candidate among the inspected declarations; they do not prove its actual physical or lifecycle effects. The header does not document fade duration, whether it changes collision/physics, whether it works in RLBot-managed Soccar, or whether its call is idempotent. Those remain game acceptance questions; “fade out” in a method name is not proof of a particular visual or physics effect.

## Soccar access and existing callers

The SDK declares `GameWrapper::GetCurrentGameState()` and `GetGameEventAsServer()` returning `ServerWrapper` (`GameWrapper.h:67, 70`), and `ServerWrapper::GetBall()` returning `BallWrapper` (`ServerWrapper.h:21`). MCT Power Shots uses a single Soccar match with the configured `MultiBallMutator.One` (`src/my_career_training/adapter.py:112–119`), so the generic server/ball wrapper route is the relevant declared API shape.

There is one read-only MCT use of this wrapper path: `MyCareerTraining.cpp:465–506` gets current server state and `server.GetBall()`, then reads `GetbFadeOut()` and `GetbEndOfGameHidden()` only inside a validated **stock built-in training** probe. It does not call a visibility setter and does not establish behavior in MCT Power Shots. A search of the pinned public default-plugin tree at `work/research/bakkesmod-default-plugins` (commit `f412cd66ce0735be4aeb21ca41325337eb959aa0`) found no `FadeOutBall`, `FadeInBall`, actor-hidden, destroy-ball, or reset-ball callers to serve as an implementation example.

The current Power Shots source itself has no native visibility writer (`work/campaign/attempt-end-01.md`). Its Python worker controls the ball through RLBot state writes, while the BakkesMod plugin renders the card. Crossing those two owners needs an explicit bridge message; it should not retain a `BallWrapper` across packets. `ObjectWrapper` exposes `memory_address`, but the inspected object/ball headers provide no stable actor ID. Re-query and validate the current wrapper for each operation; session ID, attempt ID, server identity, and wrapper address together can guard against stale effects, but address reuse remains a runtime risk.

## One future adapter contract

1. **Scope:** apply only while the existing offline ownership and freshness checks pass, the game is in an unpaused non-replay/non-online match, and session state is `kind=training`, `state=training`, `worker_running=true`, `lesson_id=power-shots`. `TrainingLessonInput::lessonScope` already encodes those lesson/session gates (`plugin/include/TrainingLessonInput.h:154–164`); also use the plugin's `offlineReady_` / `ownedOfflineNow()` checks (`plugin/src/MyCareerTraining.cpp:580–589, 1285`). Do not key off `IsInGame()` alone.
2. **Trigger:** send a terminal message containing the bridge/session identity, attempt ID, and outcome. Fade only for `outcome=timeout`; preserve the scored-ball behavior on success. A distinct message is better than polling `latest_attempt`, which is retained as history and does not appear in the coaching phase with a current attempt ID. This event is separate from `attempt_ack`.
3. **Apply:** on a game-thread-safe callback, re-fetch `GetCurrentGameState()` (fallback `GetGameEventAsServer()` if that is the established path), then `GetBall()`; validate server and ball wrappers before calling `FadeOutBall()`. `GameWrapper::Execute(std::function<void(GameWrapper*)>)` is declared for calls from a different thread (`GameWrapper.h:92–94`), but the callback's effect in this mode still needs verification. Read `GetbFadeOut()` only as a flag confirmation, not proof that pixels disappeared.
4. **Own and restore:** retain only a lease tuple for the same bridge/session/attempt/server/ball identity, not the wrapper object itself. Call `FadeInBall()` before applying the next reset state and on Return/session teardown only if the current server and ball still match the lease and MCT applied the fade. If the actor has changed, clear the lease without fading a new actor. Do not restore over a changed owner or user/native change; the current headers expose no independent ownership token.
5. **Acknowledgement:** issue fade at terminal timeout without waiting for file-save ack, so the visual follows the lesson clock. Keep the faded state while retry is blocked on save. On manual/automatic retry, restore in coordination with the worker's whole-state reset. Return is not gated on attempt acknowledgement, so restore before stopping the owned worker/game path. Report requested, API-called/applied, visually observed, and restored as separate statuses; current bridge has no visibility-operation acknowledgement.

## Minimum acceptance and remaining unknowns

In an isolated owned offline Power Shots run, verify timeout calls the fade once on the current Soccar ball; the ball becomes visually absent at the requested time; determine whether it remains collidable or can still produce touches/goals; and verify a timed-out ball is restored on manual retry, delayed auto-retry, Return, worker/session loss, and ball-actor replacement without changing the Human car or score. Test success separately to ensure normal goal/replay presentation is preserved. Confirm a user/native fade state is not claimed or overwritten. If `FadeOutBall()` is not supported or cannot be reliably restored in this context, do not substitute actor destruction, raw hidden flags, or an out-of-arena parking write without a separate lifecycle contract.
