# STOCK-COMPONENT-REUSE-01 — stock UI reuse boundary

## Scope and evidence level

Static source and package-metadata review only. This extends [native UI](nativeui-01.md), [pack browser](native-pack-browser-01.md), and [row composition](native-pack-row-01.md); those reports cover visual conventions and widget behavior. I used the already-pinned FFDec CLI on the exact MainMenu movie and exported only the target widgets and bases to private working files. No game, runtime class lookup, compile, or package edit was performed.

The coordinator independently parsed the XML class/script tables and verified the movie, XML and ten selected export hashes. The [sanitized metadata receipt](../evidence/stock-component-reuse-01.json) records those checks; raw scripts, movie data and artwork remain private. The checked-in compiled manifest below is publication-baseline evidence, not proof that the currently inspected authored source was compiled or deployed; see [build provenance](build-01.md).

## Current MCT composition

The authored `MctRootMenu` is composed into the stock `MainMenu` movie. The pinned `GFX_MainMenu_SF.upk` is 3,418,271 bytes (SHA-256 `d3e0eeadd2766fa1fb10c2d220c22a84ab2f26fb6bbb89b414a26ef1fd6e2f65`); its exact `MainMenu` movie is 1,136,465 bytes (SHA-256 `57582fb10fe1e2551989bf15d8aec1df8b62392903974a1e8ea40ac2b1734ec0`). The candidate manifest lists three authored classes and seven JSON codec classes; it says game classes are not linked and runtime/production readiness are false (`native_ui/compiled/manifest.json:6–54`). The documented composition appends the authored DoABC to the existing movie and remaps its screen/root entries (`native_ui/README.md:76–89,100–125`).

`MctRootMenu` extends `tagame.menus.BranchingMenu`, uses CLIK `Button`/`UIComponent`, and draws its browser rows, tabs, details, and panel controls with authored sprites and text fields (`native_ui/menus/MctRootMenu.as:30–52,121–145,820–895,1515–1752`). It does not currently use the stock list, legend, or category-button classes. The MainMenu SDK is passed as an external compiler library; those declarations are not copied into MCT's ABC (`native_ui/README.md:112–125`).

The MainMenu movie's ABC class table contains `tagame.controls.ButtonLegend`, `tagame.controls.CategoryButton`, and `tagame.controls.ModalScrollingList`, plus their generic bases. Selected-class exports of these definitions succeeded directly from this exact MainMenu movie. The training-specific `TrainingSequenceListItemMovie`, `controls.TrainingSequenceListItem`, and `tagame.controls.ModalListItemRenderer` are absent from the ABC `instance_info` class-name table; an exact selected-class export request returned no AS files. MainMenu does contain generic `projectx.controls.StateTweenListItemRenderer` and CLIK `ListItemRenderer`, but they do not supply the missing training row subclasses.

The existing `MainMenu` movie also has `ImportAssets2` tags for `../GFX_Fonts/gfxfontlib.swf` and `../GFX_Shared/SharedComponents.swf`. In FFDec's XML both tags have empty symbol/name arrays (0 imported symbols each). The row movie imports these same two external SWFs. Thus the imports are present in MainMenu, but their presence does not establish availability of the training row class or all of its symbols in MCT's runtime domain (`MainMenu.xml:73,151`; row metadata in [pack row composition](native-pack-row-01.md)).

The 712 entries printed by FFDec `-dumpAS3` match the number of `script_info` records; they are not the class-definition count. The XML has 712 `script_info` records, 714 `instance_info` records, 714 `class_info` records, and 714 distinct class traits. Two script records carry `TraitMethodGetterSetter` entries named `LOCTEXT` and `NSLOCTEXT` rather than classes; four other script records each carry two class traits. This reconciles the 712/714 counts without treating them as the same population (`MainMenu.xml` ABC tables; private receipt). The movie's 95 `SymbolClass` pairs include `MainMenuScreen`→0, `RootMenuMovie`→83, `GarageMainMenuMovie`→92, and `CareerMenuMovie`→93. The three MainMenu-defined widget classes have no `SymbolClass` entries; the training row movie is absent from both its ABC class table and `SymbolClass`. `ModalListItemRendererMovie` and `BasicScrollBar` likewise have no MainMenu class or `SymbolClass` entry. These are movie-local absences; external/shared runtime resolution remains unknown (`MainMenu.xml` `SymbolClassTag`, line 247525).

## Stock class dependency boundary

The Custom Training browser movie inventory (535 class entries; movie SHA-256 `c55ff890a0255a9ee5cdd347c255271cb78ce61e137f45ded1d9cfb18f925098`) contains `ButtonLegend`, `CategoryButton`, `ModalScrollingList`, and `TrainingSequenceListItemMovie` (`classes.txt`, SHA-256 `1ea85ad11126af9c5f2cf1f95e4e894570377d2b155f75600624e442c711fb32`). That establishes definitions in the browser movie, not in MCT's MainMenu target.

The MainMenu exports of `ButtonLegend`, `CategoryButton`, and `ModalScrollingList` have the same SHA-256 values as their earlier stock TrainingMenu/TrainingBrowser exports, so these are byte-identical class bodies in the reviewed movies. This confirms duplicated stock definitions across movie assets; it does not establish whether GFx shares one definition or creates separate per-movie class objects. Since the MCT composition targets MainMenu, reference the existing MainMenu definitions and avoid adding duplicate QNames to the authored ABC.

## Feasible paths

1. **Reference the existing MainMenu definitions.** `ButtonLegend`, `CategoryButton`, `ModalScrollingList`, and their inspected generic bases are already defined in the MainMenu movie. Compile MCT references against the existing SDK declarations without adding duplicate class bodies. Runtime-test symbol lookup and required control/timeline children before using them in the MCT browser.
2. **Keep MCT's authored row renderer where it fits.** Its stable-key selection, focus, text, and sprite states are already authored. A stock list can be considered separately, but its default renderer and scrollbar names do not resolve from the reviewed MainMenu class inventory; provide a compatible MCT renderer or prove the named symbols resolve.
3. **Add or load the stock training row only with its missing dependency closure.** The row's training-specific classes are not in MainMenu. Either compose the row classes and their symbols with a collision check, or investigate nested `TrainingBrowserMenu.gfx` loading if the host supports it. No MCT loader path or separate `ApplicationDomain` contract is verified.

## Required runtime proof

On the exact composed MainMenu candidate in an owned offline session, query each required class by fully qualified name in the actual GFx domain; verify `ButtonLegend`'s current-domain glyph lookup; instantiate the controls with their required timeline/assets; and check class/QName resolution order. For a list, test the default renderer/scrollbar and an authored-row override. Then verify rendering, focus/controller navigation, missing-glyph fallback, movie close/reopen, and resize. Static class presence and an external compile SDK cannot establish these effects. Keep `runtime_verified` false until that acceptance is recorded.
