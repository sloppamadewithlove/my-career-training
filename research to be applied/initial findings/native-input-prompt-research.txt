# Native controller prompts and stock HUD components

Read-only source mapping from the existing private ActionScript exports, authored candidate UI, and public BakkesMod SDK headers. No game input or runtime capture was performed. These findings establish source behavior, not that a particular movie has all expected symbols at runtime.

## Confirmed stock route

- `InputTypes` distinguishes PC, 360, PS3, PS4, Xbox One, Switch Pro, and single Joy-Con (`<private research>/private-main-menu-classes/scripts/projectx/api/InputTypes.as:6,8,10,12,14,16,18`). The UI listens through `ShellAPI.onInputTypeChanged`; `InteractionManager` sets PC to `UNBOUND`, gamepad to `BOUND`, updates mouse-child handling, and dispatches `INPUT_TYPE_CHANGED` (`.../projectx/managers/InteractionManager.as:165,360,364,368,370,371`).
- Focus navigation is handled separately from prompt rendering: the manager routes directional nav equivalents through CLiK `FocusManager.findFocus`, preserving the event's controller index (`.../projectx/managers/InteractionManager.as:333-353`).
- `SystemIconManager` maps nav equivalents to tokens such as `GP_A`, `GP_B`, and D-pad directions (`.../projectx/managers/SystemIconManager.as:79-114`). On input-type change it selects glyph suffixes: PS4 tries `_PS4` then `_PS`; 360 uses `_XB`; Xbox One uses `_XB1` (`.../projectx/managers/SystemIconManager.as:30-42,352-398`). It resolves names such as `GamepadIcon_A_PS4`, `GamepadIcon_A_XB1`, `PCIcon_LMouse`, and `PCIcon_Backspace` through `ClassUtils.getClassDefinition(stage, ...)` (`.../projectx/managers/SystemIconManager.as:318-341,401-436,446-451`). Thus DS4/PS4 and Xbox switching are supported when `ShellAPI.inputType` reports the corresponding type and those timeline symbols exist.
- Prompt sizing is data-driven. `updateImageSubstitutionForTextfieldByType` scales icon height from text line height, preserves bitmap aspect ratio, and accepts an explicit baseline shift (`.../projectx/managers/SystemIconManager.as:144,197-203`). `replaceMarkupWithIcons` exposes scale and baseline arguments (`.../projectx/managers/SystemIconManager.as:228-248`). `LegendElement` uses scale `1.6` and baseline `-2` (`.../tagame/controls/LegendElement.as:74,94-95`); `ControllerIconButton` uses scale `1` and baseline `+4` (`.../tagame/controls/ControllerIconButton.as:120-131,196-203`).
- `ButtonLegend` is the stock action/footer legend. It accepts `ButtonLegendData`, supports add/remove and sizing APIs, and changes presentation on input-type changes (`.../tagame/controls/ButtonLegend.as:72,98-116,133-135,212-234,318-350`). `LegendElement` renders the controller token plus action text in gamepad mode; in PC mode it creates the configured PC button class and labels it with the action string/override (`.../tagame/controls/LegendElement.as:74-118,137-176`). That PC button label is an action label, not a lookup of the player’s bound keyboard key. The class also has optional input-dependent `ControllerIconButton` behavior: `setButtonMarkup`, `alwaysShowIconForGamepad`, and state-driven visibility (`.../tagame/controls/ControllerIconButton.as:99-117,136-152,152-203`).
- Localization helpers are present as root-level functions: `LOCTEXT` calls the game's `Localize("Global", key, "UIText")`; `NSLOCTEXT` passes an explicit namespace (`.../scripts/LOCTEXT.as:6-14`, `.../scripts/NSLOCTEXT.as:6-18`). Outside the game they return the supplied English fallback.

## Evidence of actual use and authored-menu boundary

The recovered stock `TrainingBrowserMenu` declares a timeline `mcButtonLegend`, selects `GenericModalSquareMenuButton`, subscribes to `INPUT_TYPE_CHANGED`, and adds localized Close/Search/Clear actions with `GP_B`/`GP_X` markers (`<private research>/private-workshop-movies/export-training/scripts/menus/TrainingBrowserMenu.as:112,205-206,272-286,569-592`). This is concrete stock menu usage, not proof about the unrecovered in-game shot HUD.

The current authored menu code in `<candidate checkout>/native_ui/menus/MctRootMenu.as` uses CLiK focus, `NavigationCode`, keyboard events, and `TextFieldEx` (`:254,369-371,413,472,943-959`), but a bounded search of `native_ui` found no `ButtonLegend`, `SystemIconManager`, `ControllerIconButton`, glyph-token, or localization-helper references. Its focus/prompt path is currently custom. The native UI build notes compile against private menu SDKs as *external* libraries (`.../native_ui/README.md:76-83,112-118`); the compiled root manifest lists only authored classes plus the JSON library and says `game_classes_linked: false`, `runtime_verified: false` (`.../native_ui/compiled/manifest.json:10-43,52-54`). So stock ActionScript APIs can be referenced through the private SDK, but they are not automatically present as definitions in the authored ABC.

The relevant icon and button names remain timeline dependencies. In the searched exports, `GamepadIcon_*`, `PCIcon_*`, `NewBasicButtonLegendButton`, and `GenericModalSquareMenuButton` appear as lookup strings, not recovered symbol definitions. `ButtonLegend.legendButtonName` logs when its class cannot be found (`.../tagame/controls/ButtonLegend.as:98-116`); icon lookup returns null without a stage symbol (`.../projectx/managers/SystemIconManager.as:318-341`). A new menu therefore needs compatible linked movie symbols or a fallback; a successful compile alone does not establish visible glyphs.

The inspected public BakkesMod SDK offers binding lists and drawing primitives, not this native localized glyph route: `SettingsWrapper::GetAllPCBindings`/`GetAllGamepadBindings` (`<private research>/BakkesModSDK/include/bakkesmod/wrappers/SettingsWrapper.h:12-19`), `GameWrapper::RegisterDrawable`/`IsKeyPressed` (`.../GameWrapper.h:94,122`), and Canvas text/texture drawing (`.../canvaswrapper.h:23-30`). No API for the active localized Rocket League button glyph was found in these inspected declarations.

## Unknowns and best runtime capture

- No runtime proof that the authored menu's movie stage exposes the stock glyph definitions or that its private SDK resolves every class import.
- No proof that Windows reports a DualShock 4 as `GamepadPS4`; the recovered Flash code only proves what it does if that type is reported. Nor is the player’s real keyboard binding turned into a keycap label by `ButtonLegend` itself.
- Capture the same authored screen with keyboard/mouse, a DS4, and an Xbox controller: record `ShellAPI.inputType`, verify Close/Confirm/Back prompts change, and check that `GamepadIcon_A_PS4`/`_XB1` render at the intended scale. Include resize/UI-scale and controller focus movement. This isolates switching, symbol availability, sizing, and focus without treating source evidence as runtime acceptance.
