Training browser identity and availability research
Read-only source inspection of <candidate checkout>. No tests were run. Findings describe source and unit-contract behavior, not game acceptance.

Summary
The browser uses typed stable row identities and stores favorite display metadata separately from action authority. Core Lessons and the Power Shots rank route exist in source. Featured Custom Training packs remain visible and favoritable but are explicitly unavailable offline. Workshop launch and general plugin activation are intentionally gated; development-only host paths do not prove supported player functionality.

Identity and metadata
- Core Lessons: training/catalog.py:195-203 returns the fixed catalog. Native rows use key lesson:<id>, type lesson, and the slug ID (plugin/include/NativeCareerLayout.h:1600-1617). Title/description come from catalog rows. Power Shots says Choose rank; other core lessons say Start lesson.
- Featured packs: training/packs.py:27-107 is a six-entry metadata-only list with title, creator, listed rank, code and source; the native host independently allowlists the same six IDs/codes (plugin/include/NativeTrainingPackHost.h:23-35). Browser IDs are lesson:pack:<pack-id> (NativeCareerLayout.h:1618-1632).
- Workshop/local library: curated creator references use stable slugs and Workshop IDs (src/my_career_training/content.py:59-110). Steam files are individually identified as steam:<workshop-folder-id>:<16-hex-path-token>; imported files as imported:<sha256> (workshop.py:94-169). Catalog reference rows retain their slug and point to launch_id only when exactly one local package matches; multiple files require explicit exact selection (workshop.py:176-199). Native binding verifies paths under the running game's Steam Workshop tree and only aliases a catalog row if its launch_id matches exactly one bound package (NativeCareerLayout.h:697-754).
- Public Workshop/Mods catalog: discovery IDs are source-namespaced (steam_maps:<numeric-id>, bakkes_maps:<numeric-id>, bakkes_plugins:<numeric-id>), with source and numeric ID separated. Rows are catalog_only, installed state unknown, and cannot launch/activate (community_discovery.py:755-778). Native browser keys become workshop:<source:id> or plugin:<numeric-id> (NativeCareerLayout.h:1657-1671, 1675-1708).
- Curated plugin catalog currently contains ID 223, a snapshot rather than a compatibility claim (community_plugins.py:107-127). A live lookup fetches release metadata by numeric ID; a download is retained in the private cache as downloaded_not_enabled (community_plugins.py:130-205, 240-255).

Refresh and availability
- Workshop inventory is scanned at bootstrap, on explicit Refresh library, and before adding a unified browser Workshop favorite; the legacy workshop_favorite toggle also refreshes first. It is not scanned every tick (bootstrap.py:253-260; bridge.py:282-288, 1124-1125, 1192-1199; workshop.py:171-175). Public catalog pages are fetched only by explicit browse/scroll, with bounded pages and rows; generations discard stale worker results (bridge.py:387-433, 481-545). Catalog thumbnails are scheduled from validated results, not a URL from a saved favorite or native command (bridge.py:517-522).
- Core lesson availability uses lessonReady: phase must be ready/idle/training; busy, incomplete setup, running/likely worker, or active native pack blocks; a saved unfinished career fixture does not block training (NativeCareerLayout.h:1170-1188).
- Pack rows have primary_enabled=false with “Unavailable offline” (NativeCareerLayout.h:1625-1631). docs/TRAINING_PACKS.md:53-71 records the owned offline attempt: Training/GetTrainingData returned FeatureDisabled, the game stayed at frontend, and no pack loaded. An exact-ID native request controller exists, but that is not a successful player route.
- Workshop public rows open the canonical source page. Python marks every map can_launch=false and the legacy play_workshop path rejects before launch (workshop.py:200-244, 258-283; map_guard.py:17-20). A native model can bind verified Steam packages only in an owned offline scope, but NativeWorkshopContext says game-tested and production-allowed are false; NativeWorkshopLauncher is development-only, and callback return is not proof of load (plugin/include/NativeWorkshopContext.h:38-64; NativeWorkshopLauncher.h:3-14, 30-45). Imported maps and Epic launch remain unavailable.
- Mods support catalog browsing, release lookup and download to private cache. There is no product activation action; UI/backend labels downloads not enabled (NativeCareerLayout.h:325-329, 1680-1708; bridge.py:344-383). Production plugin profiles are empty and production_eligible always false (community_session.py:85-93). A separate developer trial is not a general Mods activation path.

Favorites and stale rows
- storage.py:42-61 accepts at most 512 unique (type,id) entries of types lesson/workshop/plugin, with only title/subtitle/detail snapshots. It rejects malformed IDs, duplicate identities, oversized/control metadata and extra action fields.
- bridge.py:635-698 resolves favorite additions from live rows, saves bounded display snapshots, and never saves actions. Favorite remote target resolution accepts only workshop IDs in steam_maps:<decimal> or bakkes_maps:<decimal>, and numeric plugin IDs; it reconstructs canonical official URLs and never trusts saved URLs (bridge.py:547-598).
- Native Favorites merges current rows from Lessons/Workshop/Mods and appends saved snapshots when absent (NativeCareerLayout.h:1552-1598). Missing local/lesson items show Unavailable. A strict saved plugin ID can still Check release; a strict remote map ID can still Open source. Favorite toggling remains allowed when primary launch is disabled, so unavailable rows can be removed (NativeCareerLayout.h:655-670). Browser images use the same row key across original tab and Favorites (NativeCareerLayout.h:1484-1508; bridge.py:118-129).

Rank route
Power Shots is the only core lesson with a rank menu in the inspected layout. Selecting its Lessons/Favorites row enters the lesson page without launching; that page lists eight intended challenges (Bronze through Supersonic Legend) and Start shot 1. Rank selection dispatches lesson_scenario with the currently stored scenario plus rank; Start dispatches start_lesson with low-side-pass and the acknowledged rank (NativeCareerLayout.h:688-692, 1793-1833). Rank titles are explicitly not certified competitive ranks (training/scenarios.py:13-25, 155-165, 255-295). Other core lessons start directly. A featured pack's displayed rank is source metadata only.

Existing coverage and limits
- plugin/tests/native_training_browser_tests.cpp:343-408, 440-483 covers separate rank route, eight ranks plus Start, current-situation retention, stale generation refusal, shot-one payload, Power Shots via Favorites, and pack unavailable/favorite removal. tests/test_bridge.py:152-162, 571-584 covers scenario persistence and lesson favorite snapshots; pack favorite identity is tested at 1487-1498.
- tests/test_workshop.py:21-150 covers local package discovery, filtering/favorites, traversal/link exclusions, multi-file selection and Epic-unavailable behavior. plugin/tests/native_workshop_catalog_tests.cpp:149-468 covers catalog navigation/pagination/stale choices and disabled activation.
- tests/test_community_discovery_bridge.py:64-334 covers bounded browse/cancel, canonical links, plugin selection validation and absence of an activation action. tests/test_community_plugins.py:167-277 covers curated entry and numeric-ID lookup/cache. tests/test_storage.py:233-247 covers favorite metadata validation. tests/test_native_training_packs.py:53-61 pins Python/native pack table parity.
- Gaps: these are source/unit contracts, not in-game proof of browser/rank/favorite interaction or Workshop loading. I found no tests referencing _favorite_catalog_target/_favorite_catalog_item or asserting a saved remote favorite can resolve after its page disappears; fallback code exists but its restart path lacks focused test evidence. Project status explicitly describes the separate rank/settings candidate as source-ready, not loaded (docs/PROJECT_STATUS.md, “Separate rank/settings candidate”).
