# Native menu customization precedents

Source review: 23 October 2026. These examples establish that game menus can be changed by mods. They use different levels of access, though: editing menu artwork, injecting a custom panel into an existing screen, and suppressing or rerouting native button behavior are separate capabilities. None by itself proves a safe Rocket League main-menu replacement.

| Example | What the checked source demonstrates | Full replacement of the game's main menu? |
|---|---|---|
| Batman: Arkham City | Export, edit, and re-import Scaleform movies from UE3 packages; change sprites/text in individual UI layers. | Not demonstrated. The tutorial describes individual menus and HUD layers. |
| SkyUI (Skyrim) | Ship replacement SWF files for several distinct in-game menus and check their expected interface versions. | No. It replaces selected screens over time, not the whole interface or main menu. |
| Fallout 4 MCM | Inject a custom SWF child into the existing `Interface/MainMenu.swf` movie and register native GFx calls. | No. The checked code adds MCM to the existing menu movie; it does not remove or replace the native menu tree. |
| FancyMenu (Minecraft Java) | At runtime, modify native screen widgets: reposition, relabel, hide, suppress their input, and invoke an existing widget's click handler. | It can make a screen's visible layout custom, but the code operates on Minecraft's existing screen/widget system; it is not an asset/package replacement. |

## What transfers

**Batman: Arkham City is the closest asset-format comparison.** A mod author describes Arkham City’s UI as Scaleform movies stored in `.upk` packages. The workflow is to export the SWF/GFX movie, edit its sprites or text, import the changed movie into a package patch, then apply that patch to the game packages. The author distinguishes layers for individual menus and HUD elements, so this is evidence for editing native UI content—not evidence that the menus' button logic can be replaced or that the whole main menu was successfully redesigned. It is a community how-to, not Rocket League documentation. [Tutorial: UI/HUD editing with Scaleform](https://www.nexusmods.com/batmanarkhamcity/articles/48)

**SkyUI proves individual in-game menus can be replaced while keeping the game’s style.** Its release notes say the project ships selected menus incrementally—Inventory, Barter, Container, Magic, Favorites, and others—rather than rebuilding the entire interface. The pinned build script copies compiled SWFs listed in `filegroup_interface.txt` into the mod’s `Data/Interface` tree, then builds and installs an archive. Its Papyrus code checks each opened menu’s expected SWF symbols and version markers. That is a practical version-compatibility safeguard; it is not proof of custom native button routing or a replacement home screen. [SkyUI release notes](https://github.com/schlangster/skyui/blob/835428728e2305865e220fdfc99d791434955eb1/dist/Data/Readme%20-%20SkyUI.txt#L56-L76), [interface file list](https://github.com/schlangster/skyui/blob/835428728e2305865e220fdfc99d791434955eb1/dist/filegroup_interface.txt#L1-L18), [copying and archive install script](https://github.com/schlangster/skyui/blob/835428728e2305865e220fdfc99d791434955eb1/dist/make_archive.pl#L401-L485), [menu version checks](https://github.com/schlangster/skyui/blob/835428728e2305865e220fdfc99d791434955eb1/dist/Data/Scripts/Source/SKI_Main.psc#L1236-L1364)

**Fallout 4’s Mod Configuration Menu is a strong runtime GFx example, but not a main-menu replacement.** At a pinned source revision, its F4SE plugin checks that the current movie is `Interface/MainMenu.swf`, creates an `mcm` object, registers native functions, loads `MCM.swf`, and adds that movie as a child of `root.Menu_mc`. This demonstrates a custom in-game panel with host callbacks inside a stock GFx menu. The same code depends on Fallout/F4SE-specific movie and input APIs; the checked block does not hide or replace the existing menu buttons. [Pinned injection and function-registration code](https://github.com/reg2k/f4mcm/blob/e2b187a82e87e63571f6f59ec3c29d505e02779e/src/ScaleformMCM.cpp#L3276-L3294), [MainMenu movie injection](https://github.com/reg2k/f4mcm/blob/e2b187a82e87e63571f6f59ec3c29d505e02779e/src/ScaleformMCM.cpp#L3565-L3618)

**FancyMenu is the clearest example of changing visible controls and preserving their actions.** Its screen hook discovers the current screen’s widgets and adds custom elements to that screen’s child list. A vanilla-widget adapter can change labels/position or mark a button hidden. Mixin hooks suppress hidden widgets’ rendering and reject their clicks or keyboard focus; `MimicButtonAction` resolves a vanilla widget and calls its original `onClick`. This is a real route from a custom-looking control back to an existing game action. It works by Java mixins against Minecraft’s widget classes, so it provides a behavioral pattern, not code or API that can be reused in Rocket League. [Screen customization hook](https://github.com/Keksuccino/FancyMenu/blob/b8472ae133edfa8cfd117db2026333ac8691889b/common/src/main/java/de/keksuccino/fancymenu/customization/layer/ScreenCustomizationLayer.java#L2281-L2315), [vanilla widget relabel/hide/position](https://github.com/Keksuccino/FancyMenu/blob/b8472ae133edfa8cfd117db2026333ac8691889b/common/src/main/java/de/keksuccino/fancymenu/customization/element/elements/button/vanillawidget/VanillaWidgetElement.java#L698-L770), [hidden-widget rendering](https://github.com/Keksuccino/FancyMenu/blob/b8472ae133edfa8cfd117db2026333ac8691889b/common/src/main/java/de/keksuccino/fancymenu/mixin/mixins/common/client/MixinAbstractWidget.java#L155-L176), [click/focus rejection](https://github.com/Keksuccino/FancyMenu/blob/b8472ae133edfa8cfd117db2026333ac8691889b/common/src/main/java/de/keksuccino/fancymenu/mixin/mixins/common/client/MixinAbstractWidget.java#L326-L350), [reuse existing click action](https://github.com/Keksuccino/FancyMenu/blob/b8472ae133edfa8cfd117db2026333ac8691889b/common/src/main/java/de/keksuccino/fancymenu/customization/action/actions/other/MimicButtonAction.java#L31-L40) and [widget callback](https://github.com/Keksuccino/FancyMenu/blob/b8472ae133edfa8cfd117db2026333ac8691889b/common/src/main/java/de/keksuccino/fancymenu/customization/widget/WidgetLocatorHandler.java#L96-L115)

## Rocket League boundary

These precedents answer “is native UI modding possible in games?” with **yes**. They do not settle “can this safely replace Rocket League’s current main menu?” The Arkham and SkyUI approaches alter or override game UI files; that does not meet the requirement to leave the Steam installation intact merely because a backup or later file verification might restore it. Fallout MCM proves that a plugin can modify a GFx movie when its game-specific extension exposes that movie root. FancyMenu proves a mod can suppress and reuse button actions when its runtime hooks expose the game's widget model. Neither supplies those APIs for Rocket League.

The current My Career plugin’s `CreateModal` trial is only a native confirmation/dialog surface. The full-screen `PluginWindow` is an overlay. The repository documents that neither changes Rocket League’s top-level buttons or menu tree ([native dialog trial](../NATIVE_DIALOG_TRIAL.md), [plugin UI boundary](../../plugin/README.md)). The current research candidate is therefore the live, process-local GFx/menu-tree route already documented in [Native Rocket League menu research](../NATIVE_MENU_RESEARCH.md): first prove on the exact Steam build which objects own the buttons, how callbacks can be replaced without also invoking the stock action, and how ordinary menus return after exit. Until then, these are precedents and hypotheses—not a verified mod, a safe installer, or proof that the user's Steam game can remain untouched and online-ready.
